1. OVERVIEW
===========

The My Calendar feature is a comprehensive calendar system that provides users with a unified view of all their scheduled activities, tasks, events, and important dates. It integrates multiple data sources including tasks, events, tickets, leaves, and follow-ups into a single, easy-to-navigate calendar interface.

Key Features:
- Unified calendar view with multiple data sources
- Real-time event filtering and type selection
- Permission-based content display
- Integration with employee dashboard
- Multiple calendar view modes (month, week, day, list)
- Interactive event details and navigation
- Responsive design for all devices

2. MAIN MY CALENDAR INTERFACE
=============================

2.1 PRIMARY ACCESS
------------------
URL: /my-calendar
Route: my-calendar.index
Controller: MyCalendarController@index
View: resources/views/my-calendar/index.blade.php

The main My Calendar interface provides a full-screen calendar view with comprehensive filtering options and navigation controls.

2.2 INTERFACE COMPONENTS
------------------------

Filter Section:
- Type selector dropdown with options: All, Tasks, Events, Tickets, Leaves, Follow-ups
- Reset filters button for clearing all applied filters
- Real-time filter application without page refresh

Calendar Display:
- Full Calendar integration using FullCalendar.js library
- Multiple view modes: Month, Week, Day, List
- Navigation controls: Previous, Next, Today buttons
- Event color coding based on event type and status

2.3 CALENDAR HEADER TOOLBAR
----------------------------
Left Section: prev, next, today buttons
Center Section: Dynamic title showing current date range
Right Section: dayGridMonth, timeGridWeek, timeGridDay, listWeek view options

3. CALENDAR VIEWS AND NAVIGATION
=================================

3.1 VIEW MODES
--------------

Month View (dayGridMonth):
- Shows full month with events displayed as colored blocks
- Events are color-coded by type and status
- Click on date to view day details
- Hover over events for quick information

Week View (timeGridWeek):
- Displays weekly schedule with time slots
- Shows event duration and timing
- Allows for detailed time-based planning
- Scroll through time slots for full day view

Day View (timeGridDay):
- Detailed single-day view with hourly breakdown
- Perfect for daily schedule management
- Shows exact event timing and duration
- Easy navigation between days

List View (listWeek):
- Chronological list of all events for the week
- Compact view showing event details
- Easy scanning of upcoming activities
- Includes event icons and color coding

3.2 NAVIGATION FEATURES
-----------------------

Date Navigation:
- Previous/Next buttons for moving between time periods
- Today button for quick return to current date
- Click on date/week names to navigate to specific periods
- Keyboard shortcuts for quick navigation

Event Interaction:
- Click on events to view detailed information
- Event details open in right-side modal
- Direct navigation to source modules (tasks, events, etc.)
- Tooltip information on hover

4. EVENT TYPES AND DATA SOURCES
================================

4.1 SUPPORTED EVENT TYPES
--------------------------

Tasks:
- Source: Task management module
- Display: Task title, due date, project information
- Color: Based on task board column status
- Icon: fa-list
- Permission Required: view_tasks
- Includes: Assigned tasks, project tasks for clients

Events:
- Source: Event management module
- Display: Event name, start/end time, attendee information
- Color: Based on event label color
- Icon: fa-calendar
- Permission Required: view_events
- Includes: Personal events, meeting invitations

Tickets:
- Source: Support ticket system
- Display: Ticket subject, ticket number, status
- Color: Blue (#1d82f5)
- Icon: fa-ticket-alt
- Permission Required: view_tickets
- Includes: Assigned tickets, created tickets

Leaves:
- Source: Leave management system
- Display: Employee name, leave type, duration
- Color: Based on leave type configuration
- Icon: fa-plane-departure
- Permission Required: view_leave
- Includes: Approved leaves only

Follow-ups:
- Source: Deal/Lead management system
- Display: Lead/Deal name, follow-up date
- Color: Blue (#1d82f5)
- Icon: fa-thumbs-up
- Permission Required: view_deals
- Includes: Assigned lead follow-ups

4.2 DATA FILTERING LOGIC
------------------------

Permission-Based Display:
- Events only show if user has appropriate module permissions
- Content filtered based on user role and access level
- Personal data prioritized over general company data

Date Range Filtering:
- Events filtered by start and end date parameters
- Automatic date range calculation based on calendar view
- Efficient database queries with date indexing

User-Specific Content:
- Tasks: Shows assigned tasks and client project tasks
- Events: Shows attended events and created events
- Tickets: Shows assigned and created tickets
- Leaves: Shows all approved company leaves
- Follow-ups: Shows assigned lead follow-ups

7. PERMISSIONS AND ACCESS CONTROL
==================================

7.1 MODULE PERMISSIONS
----------------------

Required Permissions by Event Type:
- Tasks: view_tasks permission
- Events: view_events permission
- Tickets: view_tickets permission
- Leaves: view_leave permission
- Follow-ups: view_deals permission

Permission Levels:
- none: No access to event type
- owned: Access to own events only
- added: Access to created events
- both: Access to owned and created events
- all: Access to all events

7.2 USER ROLE RESTRICTIONS
---------------------------

Employee Role:
- Access to assigned tasks and personal events
- View own tickets and leave applications
- See company-wide approved leaves
- Access to assigned follow-ups if lead agent

Client Role:
- Access to project tasks for assigned projects
- View project-related events
- Limited ticket access (own tickets only)
- No access to internal leave information

Admin Role:
- Full access to all calendar events
- Complete permission override capability
- System-wide calendar management
- User calendar configuration access

9. URL ROUTES AND ENDPOINTS
===========================

9.1 PRIMARY ROUTES
------------------

Main Calendar Route:
GET /my-calendar
Route Name: my-calendar.index
Controller: MyCalendarController@index
Purpose: Display main calendar interface and return event data

9.2 RELATED ROUTES
------------------

Event Detail Routes:
- GET /tasks/{id} - Task details (route: tasks.show)
- GET /events/{id} - Event details (route: events.show)
- GET /tickets/{id} - Ticket details (route: tickets.show)
- GET /leaves/{id} - Leave details (route: leaves.show)
- GET /deals/{id} - Deal details (route: deals.show)

Dashboard Integration:
- GET /dashboard/employee - Employee dashboard with calendar widget
- GET /dashboard/private-calendar - Alternative calendar access

9.3 API ENDPOINTS
-----------------

Calendar Data API:
URL: /my-calendar
Method: GET
Parameters:
- start: Start date for event range (YYYY-MM-DD)
- end: End date for event range (YYYY-MM-DD)
- type: Event type filter (task|events|tickets|leaves|follow_ups|all)

Response Format: JSON array of event objects
Event Object Structure:
{
    "id": "event_id",
    "title": "Event Title",
    "start": "2024-01-01T09:00:00",
    "end": "2024-01-01T10:00:00",
    "event_type": "task|event|ticket|leave|follow_up",
    "extendedProps": {
        "bg_color": "#color_code",
        "color": "#text_color",
        "icon": "fa-icon-name"
    }
}

10. TROUBLESHOOTING AND SUPPORT
===============================

10.1 COMMON ISSUES
------------------

Calendar Not Loading:
- Check JavaScript console for errors
- Verify FullCalendar library loading
- Confirm user permissions for calendar access
- Validate date range parameters

Events Not Displaying:
- Verify module permissions (tasks, events, tickets, etc.)
- Check user role and access levels
- Confirm event date ranges
- Validate filter settings

Performance Issues:
- Review date range scope (avoid excessive ranges)
- Check database query optimization
- Monitor server response times
- Consider caching for frequently accessed data
