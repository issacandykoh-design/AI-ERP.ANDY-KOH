## 目标
- 移动端将“历史对话”收纳为按钮，点击后以弹窗展示。
- 消除移动端左右滑动，内容在竖屏下完整可视。
- 为 Web 与 Mobile 提供两套入口 HTML，通过设备路由自动切换；两端视觉风格一致。

## 技术方案
- 新增 `index.mobile.html`，加载现有打包资源与专属的 `mobile.css`、`mobile.js`。
- 在 `index.html` 增加设备检测脚本：当判定为移动端（UA 或视口宽度）时自动跳转 `index.mobile.html`。
- `mobile.css`（仅在移动端加载）：
  - 全局 `overflow-x: hidden`、`max-width: 100%`，避免横向滚动。
  - 媒体查询优化触控间距与按钮大小；浮动“历史对话”按钮与弹窗样式与 Web 颜色/字体一致。
- `mobile.js`（仅在移动端加载）：
  - DOM Ready 后，定位侧栏（通过文本“New Chat/No conversations yet”或常见侧栏容器）并默认隐藏。
  - 注入浮动按钮“历史对话”，点击后打开全屏遮罩弹窗，把侧栏节点移动到弹窗容器展示；关闭时还原位置。
  - 监听窗口尺寸变化维持无横向滚动与适配。
- 视觉一致性：沿用现有字体 `Inter`、主色系与圆角风格；弹窗按钮与 Web 组件采用相同色值与阴影（通过 CSS 变量或读取现有样式）。

## 变更文件
- 新增：`index.mobile.html`、`static/css/mobile.css`、`static/js/mobile.js`。
- 修改：`index.html` 注入设备检测与路由；（如需）`asset-manifest.json`补充新资源。

## 验证
- 在手机模式预览：按钮出现且弹窗展示对话列表；页面无横向滚动。
- 在桌面预览：仍使用 `index.html`；功能与风格不变。

## 备选与回滚
- 若后续提供 React 源码，可改为在应用内路由实现；当前方案为无源码的外部增强，随时可移除新文件并还原 `index.html` 检测脚本。
