NOTICE BOARD MODULE - COMPREHENSIVE USER GUIDE

===========================================
OVERVIEW
===========================================

The Notice Board module is a comprehensive communication system that enables administrators and authorized users to create, manage, and distribute notices to employees and clients within the organization. This module provides centralized notice management with role-based permissions, file attachments, department-specific targeting, and detailed tracking capabilities.

===========================================
MAIN NAVIGATION ACCESS
===========================================

Primary Access Point:
- Route: /notices
- Navigation: Main sidebar menu → Notice Board
- Permission Required: view_notice
- Supported User Roles: Admin, Employee (with appropriate permissions)

===========================================
NOTICE BOARD MAIN INTERFACE
===========================================

1. NOTICE BOARD INDEX PAGE
   Route: GET /notices
   Template: resources/views/notices/index.blade.php
   
   Key Interface Elements:
   
   a) Header Section:
      - Page Title: "Notice Board"
      - Breadcrumb Navigation: Dashboard → Notice Board
   
   b) Filter Controls:
      - Date Range Picker: Filter notices by creation date
        * Start Date Field: Select beginning date for filter range
        * End Date Field: Select ending date for filter range
        * Date Format: Based on company date format settings
      
      - Search Input Field:
        * Placeholder: "Search notices..."
        * Real-time search functionality
        * Searches within notice headings
      
      - Reset Filter Button:
        * Function: Clear all applied filters
        * JavaScript: Resets date range and search fields
        * Action: Reloads data table with default parameters
   
   c) Action Buttons:
      - Add Notice Button:
        * Route: GET /notices/create
        * Permission Required: add_notice
        * Opens: Right modal with notice creation form
        * Visibility: Hidden for clients and users without add permissions
   
   d) Data Table Interface:
      - Table ID: notice-board-table
      - DataTable Configuration: NoticeBoardDataTable.php
      - Columns:
        * Checkbox Column: Bulk selection (hidden for clients)
        * Notice Heading: Clickable link to notice details
        * Date: Notice creation date in company format
        * To: Target audience (Employee/Client) - hidden for clients
        * Actions: View, Edit, Delete dropdown menu
   
   e) Bulk Actions:
      - Quick Action Dropdown:
        * Delete Selected: Bulk delete multiple notices
        * Confirmation Dialog: SweetAlert confirmation before deletion
        * Permission Check: delete_notice permission required
   
   f) Export Functionality:
      - Excel Export Button: Export notice data to Excel format
      - Permission Required: Data export permissions
      - Location: Appended to #table-actions container

===========================================
NOTICE CREATION INTERFACE
===========================================

2. CREATE NOTICE FORM
   Route: GET /notices/create (Modal)
   Template: resources/views/notices/ajax/create.blade.php
   
   Form Elements:
   
   a) Recipient Selection:
      - Radio Button Group: "Notify"
        * To Employee: Target employees
        * To Client: Target clients (if client module enabled)
        * Dynamic Form Behavior: Shows/hides relevant selection fields
   
   b) Notice Details:
      - Notice Heading Field:
        * Required: Yes
        * Validation: Text input with placeholder
        * Purpose: Main title of the notice
      
      - Department Selection:
        * Field Type: Searchable dropdown
        * Options: All available departments/teams
        * Visibility: Hidden when "To Client" is selected
        * Purpose: Filter employees by department
        * Dynamic Loading: Updates employee list based on selection
   
   c) Recipient Selection Fields:
      - Employee Selection (when "To Employee" selected):
        * Field Type: Multi-select dropdown with search
        * Features: Select all/deselect all options
        * Live Search: Real-time filtering of employee list
        * User Pills: Visual representation of selected employees
        * Department Filter: Updates based on department selection
      
      - Client Selection (when "To Client" selected):
        * Field Type: Multi-select dropdown with search
        * Features: Select all/deselect all options
        * Live Search: Real-time filtering of client list
        * User Pills: Visual representation of selected clients
   
   d) Content Editor:
      - Rich Text Editor: Quill.js implementation
        * Features: Text formatting, mentions, rich content
        * Mention Support: @mention functionality for users
        * HTML Output: Stored as HTML in database
   
   e) File Attachment System:
      - Dropzone Implementation:
        * Drag & Drop: File upload interface
        * Multiple Files: Support for multiple file uploads
        * File Size Limit: Configurable maximum file size
        * File Type Restrictions: Configurable allowed file types
        * Progress Indicator: Upload progress visualization
        * Error Handling: File size and type validation
   
   f) Form Actions:
      - Save Notice Button:
        * Route: POST /notices
        * Validation: Client-side and server-side validation
        * File Processing: Handles file uploads after notice creation
        * Redirect: Returns to notice list or stays in modal
      
      - Cancel Button:
        * Route: GET /notices (redirect)
        * Function: Closes modal without saving

NOTICE EDITING INTERFACE

   c) Form Actions:
      - Update Notice Button:
        * Route: PUT /notices/{id}
        * Method: HTTP PUT via form method spoofing
        * File Handling: Processes new file uploads
        * Validation: Comprehensive form validation
      
      - Cancel Button:
        * Function: Closes modal without saving changes
        * Route: Returns to notice list

NOTICE DETAIL VIEW INTERFACE
===========================================

4. NOTICE DETAILS MODAL
   Route: GET /notices/{id}
   Template: resources/views/notices/ajax/show.blade.php
   
   Display Sections:
   
   a) Header Section:
      - Notice Title: "Notice Details"
      - Action Dropdown (if permissions allow):
        * Edit Option: Opens edit modal
        * Delete Option: Confirms and deletes notice
        * Permission-based visibility
   
   b) Notice Information Display:
      - Notice Heading: Main title display
      - Creation Date: Formatted according to company settings
      - Target Audience: Employee or Client designation
      - Recipients List: Visual display of targeted users
        * Employee Images: Profile pictures for employees
        * Client Images: Profile pictures for clients
        * Fallback: "--" if no recipients
   
   c) Content Display:
      - Description: Rich HTML content rendering
      - Formatting: Preserves rich text formatting
      - Fallback: "--" if no description provided
   
   d) Attachment Section:
      - File List: All attached files display
      - File Cards: Individual file representations
        * File Name: Original filename
        * Upload Date: Human-readable time difference
        * File Thumbnail: Preview for supported file types
        * Action Dropdown per file:
          - View Option: Opens file in new tab or lightbox
          - Download Option: Direct file download
          - Delete Option: Remove file (with permissions)
   
   e) Administrative Information (Admin Only):
      - Read Status: Shows which users have read the notice
      - User Images: Profile pictures of users who read
      - Read Tracking: Visual confirmation of notice engagement
   
   f) File Management Actions:
      - View Files: 
        * Images: Lightbox display
        * Documents: New tab opening
        * Route: Direct file URL access
      
      - Download Files:
        * Route: GET /notice_files/download/{hash}
        * Security: MD5 hash-based file access
        * Direct Download: Forces file download
      
      - Delete Files (with permissions):
        * Confirmation: SweetAlert confirmation dialog
        * Route: DELETE /notice-files/{id}
        * Dynamic Update: Refreshes file list after deletion

PERMISSION SYSTEM
===========================================

6. ROLE-BASED ACCESS CONTROL
   
   a) Permission Types:
      - view_notice: View notice list and details
      - add_notice: Create new notices
      - edit_notice: Modify existing notices
      - delete_notice: Remove notices
   
   b) Permission Levels:
      - all: Full access to all notices
      - added: Access only to self-created notices
      - owned: Access to notices targeted to user's role
      - both: Combined added and owned permissions
   
   c) User Role Restrictions:
      - Admin: Full access to all functionality
      - Employee: Department-filtered and permission-based access
      - Client: Limited to notices targeted to them
   
   d) Interface Adaptations:
      - Button Visibility: Based on user permissions
      - Column Visibility: Clients see limited columns
      - Action Availability: Permission-checked actions
      - Bulk Operations: Hidden for restricted users
